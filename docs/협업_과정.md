## 3. 협업 방식

- **초반: 기획과 목업을 동시에** — 일부 팀원이 레퍼런스 조사와 기획을 구체화하는 동안, 나머지는 PRD를 바탕으로 HTML 목업을 만들어 기획을 바로 화면으로 확인했습니다.
- **배포 이후: 브랜치로 나눠 작업하고 main에 병합** — 다섯 명 모두 GitHub에서 각자 브랜치를 만들었습니다. 맡은 UI, UX, 에이전트 기능을 고치고 테스트한 뒤 main에 병합했습니다.
- **산출물은 파일로 공유** — PRD, 목업, 코드 묶음, 기획안, 발표자료를 단체방에 파일로 올려 같은 버전을 보고 작업했습니다.
- **AI는 기능 단위로 요청** — 한 번에 전체를 만들게 하지 않고 기능을 나눠 요청했습니다. 결과는 직접 눌러 보고, 오류 증상을 다시 전달해 고쳤습니다.

## 5. 문제 대응

- **코딩 에이전트의 저장소 접근 실패** — 공동 작업자로 등록돼 있어도 GitHub 앱이 저장소에 설치되지 않으면 접근할 수 없다는 점을 확인했습니다. 변경이 팀 저장소가 아니라 팀원 개인 저장소에 반영된 사례도 찾아 팀에 공유했습니다.
- **배포 버전 되돌아감** — 운영 사이트가 초기 버전으로 돌아간 것을 팀원이 점검 중에 발견했고, 총괄이 바로 최신 버전으로 다시 배포했습니다.
